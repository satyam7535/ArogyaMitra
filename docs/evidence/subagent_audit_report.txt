### 2. Rate Limits & Nginx Edge Gateway Configuration
* **Files Examined**: `Backend/src/middlewares/security.middleware.js`, `deploy/nginx.conf`
* **Production Express Rate Limits (`createGeneralApiLimiter`)**:
  - Window: **1 minute** (`windowMs: 60 * 1000`)
  - Ceiling: **150 req/min** (`resolveRateLimit("general", 150)`)
  - *(Auth limiter for comparison: 15 req / 15 min)*
* **Production Nginx Rate Limits (`api_general` zone)**:
  - Definition: `limit_req_zone $binary_remote_addr zone=api_general:10m rate=15r/s;` (**15 req/sec**)
  - Directive under `/api/`: `limit_req zone=api_general burst=50 nodelay;`
  - *(Auth limiter zone: `rate=3r/m`, `burst=5 nodelay`)*
* **Exact Condition for Rate Limit Relaxation in Express**:
  - Relaxation is **strictly rejected** in production: if `process.env.NODE_ENV === "production"` and any bypass flag is set (`ALLOW_LOAD_TEST_RATE_LIMIT === "true"` || `ALLOW_LOAD_TEST === "true"` || `DISABLE_RATE_LIMIT === "true"`), it immediately throws `SECURITY_VIOLATION: Rate limiter relaxation for ${type} is strictly forbidden in production mode (NODE_ENV=production).`
  - Relaxation is ONLY allowed when:
    ```javascript
    process.env.NODE_ENV === "test" &&
    (process.env.ALLOW_LOAD_TEST_RATE_LIMIT === "true" ||
      process.env.ALLOW_LOAD_TEST === "true")
    ```
  - When allowed, limit defaults to `10000` or the numeric value in `LOAD_TEST_API_MAX` / `LOAD_TEST_AUTH_MAX`.

### 6. MITM Interception Proxy Demonstration
* **Files Examined**: `scripts/test_p6_mitm_proxy_demo.py`, `docs/evidence/mitm_proxy_interception_demo.txt`
* **Does it demonstrate real proxy interception with cert verification ON vs OFF?**: **YES.**
  - The script instantiates a real socket-level HTTP proxy (`RogueMITMProxy` on `127.0.0.1:9998`) terminating TLS with the untrusted local certificate `deploy/certs/arogyamitra.crt`.
  - **Verification ON (`verify=True`, Production Policy)**: Client terminates TLS handshake immediately with `SSLCertVerificationError` (`SSLError`). Zero application bytes, headers, or credentials reach the proxy.
  - **Verification OFF (`verify=False`, Insecure Mode)**: Client accepts the untrusted certificate; proxy decrypts and captures the plaintext HTTP request line, headers, and `Authorization: Bearer SECRET_WORKER_JWT_TOKEN_12345`.
